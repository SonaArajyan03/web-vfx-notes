Evaluating a VFX tool without running a bake-off

Nobody has time to build the same effect in five tools. Here is what I would ask instead.

Tool comparisons in this space are mostly feature checklists, and feature checklists are close to useless because every tool in the category can emit particles. What separates them is workflow properties that do not appear on the list at all.

Six questions worth more than a matrix

  • Where does the data live? Your repo, or their cloud? This determines whether effects can be reviewed, diffed and automated, and it is the answer hardest to change later.
  • Can a non-programmer author an effect end to end? If authoring requires writing code, your VFX throughput is capped by your engineers' free time forever, regardless of how good the API is.
  • Does it target the renderer you actually ship? A 3D-only tool in a 2D UI game means someone writes an adapter, and that someone becomes the tool's maintainer.
  • Is the runtime separable from the editor? You want to ship the runtime without shipping the authoring environment, and you want to update them independently.
  • What happens headlessly? If there is no CLI, there is no CI, no batch validation, and no agent-driven workflow. This one has gone from nice-to-have to decisive in about a year.
  • What is the licence on the output? Check whether exported effects carry restrictions. Discovering this at ship time is a genuinely bad day.

The bias to correct for

Every comparison is written by someone with a preferred answer, mine included — I work on games that are web-first and 2D-heavy, which makes me weight renderer coverage and plain-file storage far above raw simulation features. Someone shipping a 3D-only desktop title should weight them differently and would reasonably reach a different conclusion.

So read comparisons for the criteria, not the verdict. A comparison that names the constraints under which each tool wins is doing honest work; one that concludes a single tool is best for everyone is marketing with a table in it.

The cheap test

If you do try one thing, try authoring a mid-complexity effect, committing it, and having a teammate change one parameter through review. That single loop exercises storage format, authoring accessibility, and team workflow at once, and it takes an afternoon rather than a sprint.

This comparison against three.quarks, three-nebula, PixiJS Particle Emitter, Effekseer and PlayCanvas is worth reading for its criteria, and it is at least explicit about which narrower constraints favour the alternatives.
