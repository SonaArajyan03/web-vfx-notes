Notes on web game VFX
Particle effects, frame budgets, and authoring workflow for HTML5 games.

Who authors the effect matters more than which tool

Most teams do not have a VFX quality problem. They have a VFX access problem.

Ask a small studio why a screen feels flat and the answer is rarely that nobody knows how to make it good. It is that the one person who can make effects is on something else until Thursday, so the screen ships flat and gets revisited never.

That is a queue, not a craft problem, and it responds to completely different interventions.

Three ways the queue stays narrow

  • Authoring requires code. If making a spark means editing a shader or a config in a source file, only engineers make sparks. Your designers and artists have the taste and cannot reach the work.
  • Authoring requires the whole project running. If you have to build and boot the game to see an effect, iteration cost is measured in minutes and only someone with the project already running will bother.
  • Nobody can review it. Even when someone else authors an effect, if the result cannot be checked without a meeting, the expert gets pulled back in and the queue reforms around them.

What widening it actually looks like

A browser-based editor is the unglamorous answer to the first two. No install, no project setup, immediate preview — which means an artist can iterate on a burst during a coffee break and hand over a finished file. Whether the underlying engine is state of the art matters much less than whether a second person can open it.

The third needs the file format to be reviewable, which is a separate decision and the one people skip. An accessible editor writing an unreviewable blob just moves the bottleneck from authoring to approval.

The agent case, briefly

There is now a fourth author worth counting: a coding agent, supervised by whoever wanted the effect. It is good at the mechanical parts — scaffolding a variant, batch-adjusting timings, validating a project — and useless at deciding whether the result looks right, which is precisely the split you want. It needs the same things a human collaborator needs: a documented schema, plain files, and a validator that fails loudly.

All of which is to say the editor and the file format are the same decision. A free browser-based editor that writes plain JSON into your own project folder is the shape that widens the queue at both ends.
