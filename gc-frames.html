Notes on web game VFX
Particle effects, frame budgets, and authoring workflow for HTML5 games.

The frame you dropped was the garbage collector

When a web game hitches, the instinct is to blame the GPU. In my experience it is almost never the GPU.

Profile a stuttering HTML5 game on an actual phone and the pattern is usually the same: frame times are fine, fine, fine, then one frame takes 40ms, then fine again. That is not a rendering cost. Rendering costs are boring and consistent. That is a collection pause, and something in your per-frame path is producing garbage.

The rule that actually works

Treat allocation inside a hot path as a correctness bug rather than an optimisation you will get to later. Not because allocation is expensive — individually it is cheap — but because the cost is deferred, batched, and lands at a moment you do not control. A bug that manifests at a random later time is exactly the kind you want to prevent structurally rather than fix reactively.

Concretely, in anything that runs every frame:

  • Indexed loops, not .map / .filter / spread. Each of those returns a fresh array. Sixty times a second, per system.
  • Caller-owned buffers. Have the caller pass in the array or vector to write into, rather than returning a new one. Uglier signature, flat memory graph.
  • Scratch objects at module scope. One reused temp vector beats a new one per particle per frame, and the diff is usually four lines.
  • Bounded pools for bursty things. Prewarm them. A pool that grows during the burst you built it for is not a pool.
  • Update retained objects, do not recreate them. This is the one people miss with renderer objects specifically.

Where particles bite hardest

Particle systems are the worst offender because they are the one system that is simultaneously per-frame, high-count, and written by whoever needed an explosion that afternoon. A thousand particles times a fresh vector each is a million objects a minute, and it will look completely fine on the desktop you built it on.

Which is the other half of the discipline: profile on a real mid-range phone, not on your laptop with the tab focused. Desktop headroom hides every one of these until a player finds it.

The dishonest fix

The tempting response to a measured stutter is to quietly reduce the effect — fewer particles, shorter lifetime — until the number goes green. That is not a fix, it is deleting the feature and keeping the metric. Find what allocated. It is nearly always one line.
